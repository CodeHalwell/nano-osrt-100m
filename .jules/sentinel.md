## 2024-05-24 - Resource Exhaustion in Untrusted Code Execution
**Vulnerability:** Untrusted Python code executed via `subprocess.Popen` without system resource limits (`RLIMIT_AS`, `RLIMIT_FSIZE`, `RLIMIT_CPU`) allows Denial of Service (DoS) attacks via memory exhaustion or massive disk writes, even if timeout kills the process eventually. Additionally, a malicious script writing endlessly to stdout can OOM the parent process since `proc.communicate()` buffers the entire output in memory.
**Learning:** The execution sandbox relied only on timeouts and process group killing (`SIGKILL`) but lacked kernel-level resource constraints prior to process execution. The assumption that timeouts alone protect against OOM and disk exhaustion is flawed.
**Prevention:** Always use `preexec_fn` with `resource.setrlimit` when executing untrusted code with `subprocess.Popen` to strictly cap memory, CPU, and file size limits at the OS level before the child process executes.
